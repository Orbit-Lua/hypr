# AGENTS Instructions

Personal Hyprland 0.55+ Lua configuration for one workstation. Preserve current behavior unless the user asks for a change, and keep changes specific to this setup rather than generic template material. [README.md](README.md) covers layout, runtime state and the helper CLI.

## Rules

- Nacre (`~/codebase/nacre`) deploys this repository as its `hypr-config` input into a read-only Nix store path. Runtime writes go under `ctx.state_dir` (`$XDG_STATE_HOME/hypr`), never `ctx.config_dir`.
- Long-running session applications belong to Nacre; `lua/config/autostart.toml` holds only compositor-owned work.
- Structured data (autostart, menu rows, cheat sheet, effects) stays in `lua/config/*.toml`.
- `noctalia.lua` is generated by Noctalia: never edit it by hand. Tests read `tests/fixtures/noctalia.lua` instead, so theme updates leave the snapshots alone.
- Loading the config must not read command output through `io.popen`: `tests/config.lua` errors on it, and records every `os.execute` in the snapshot.
- Prefer helpers in `lua/hyprconf/util/`, `lua/hyprconf/cli.lua` and `lua/hyprconf/commands/common.lua`, and build shell commands with their `shell_quote`. Add an abstraction only to remove real duplication.
- Keep the small-module layout and the `---@class`/`---@field`/`---@param`/`---@return` annotations on typed structures.
- Run interactive or session-mutating helper commands only when the task needs them.

## Tests

- A test enters the repo only when it guards behaviour no existing test covers and fails when that behaviour breaks. Weigh this before adding each one.
- Run throwaway tests freely to check your work; keep them out of the repo unless they pass that bar.
- Run `make all` before treating a change as ready: stylua, luacheck, both snapshots, and `hyprland --verify-config` with a throwaway home. CI runs the same checks with `make fmt-check` in place of `make fmt`.
- `make keymap` compares every bind with `tests/keymap.snapshot`; `make config` compares everything else sent to Hyprland (options, rules, animations, monitors, environment, event handlers) with `tests/config.snapshot`. When the user asks for a change that alters either, regenerate the snapshot and show the diff:
  - `lua tests/keymap.lua > tests/keymap.snapshot`
  - `lua tests/config.lua "$(mktemp -d)" > tests/config.snapshot`
- `make all` does not exercise menus, screenshots, portals or session behavior; smoke-test those by hand when touched.

## Git

- Write commits in [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/) format.
- Author commits as the user alone, with no `Co-Authored-By` or other co-author trailers.
- Commit as the plan progresses. Before pushing, squash related commits into one to keep history clean.
- Push only after the user approves that push.
- Version releases with [Semantic Versioning 2.0.0](https://semver.org/).

## Docs

- Keep this file, `README.md` and every other doc concise and plain: each sentence carries information, with no filler.
