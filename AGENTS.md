# AGENTS Instructions

Personal Hyprland configuration for one workstation. Preserve bindings and runtime behaviour unless the task changes them. Read [README.md](README.md) for deployment, configuration and state locations.

## Runtime contracts

- Nacre (`~/codebase/nacre`) deploys this repository as its `hypr-config` input into a read-only Nix store path. Runtime writes go under `ctx.state_dir` (`$XDG_STATE_HOME/hypr`), never `ctx.config_dir`.
- Long-running session applications belong to Nacre; `lua/config/autostart.toml` holds only compositor-owned work.
- Home Manager owns shell and terminal configuration such as `~/.zshrc`; helpers that rewrite those files fail, so change their themes through Home Manager or Noctalia.
- `monitors.conf` and `workspaces.conf` are the user's local profile, ignored by Git; the configuration does not load them.
- Structured data (autostart, menu rows, cheat sheet, effects) stays in `lua/config/*.toml`.
- `noctalia.lua` is generated by Noctalia: change colors through its templates rather than editing the file. Tests read `tests/fixtures/noctalia.lua` instead, so theme updates leave the snapshots alone.
- Loading the config must not read command output through `io.popen`: `tests/config.lua` errors on it, and records every `os.execute` in the snapshot.
- Code under `lua/hyprconf/*.lua` and `util/init.lua` runs inside Hyprland with `hl`; `commands/` and `runtime/` run in the helper CLI and reach the compositor through `runtime/hyprctl`. `util/shell`, `util/fs`, `util/toml` and `util/json` work in both. Build shell commands with `shell.quote`, and add an abstraction only to remove real duplication.
- Annotations follow Hyprland's stubs (`/usr/share/hypr/stubs`, via `.luarc.json`): use `HL.*` types for what reaches `hl`, and `---@type` on parsed TOML and JSON, which the parsers return untyped.
- Preserve the existing `mouse = true` bind fields despite their absence from `HL.BindOptions`; change them only with an intentional keymap change.
- Keep the small-module layout and the `---@class`/`---@field`/`---@param`/`---@return` annotations on typed structures.
- Profiles are whole Lua files under `profiles/<category>/`, labelled by a first-line `-- profile: <label>`; state stores only the selected name.
- Run interactive or session-mutating helper commands only when the task needs them.

## Tests

- A test enters the repo only when it guards behaviour no existing test covers and fails when that behaviour breaks. Weigh this before adding each one.
- Run throwaway tests freely to check your work; keep them out of the repo unless they pass that bar.
- Run `make all` before finishing; CI runs `make check` to validate without formatting. Both run Luacheck, LuaLS, behavioural snapshots and Hyprland parsing with a throwaway home. `LUALS` overrides the lua-language-server binary.
- `make keymap` compares every bind with `tests/keymap.snapshot`; `make config` compares everything else sent to Hyprland (options, rules, animations, monitors, environment, event handlers) with `tests/config.snapshot`. When the user asks for a change that alters either, regenerate the snapshot and show the diff:
  - `lua tests/keymap.lua > tests/keymap.snapshot`
  - `lua tests/config.lua "$(mktemp -d)" > tests/config.snapshot`
- `make all` does not exercise menus, screenshots, portals or session behavior; smoke-test those by hand when touched.

## Git

- Write commits in [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/) format, with a body explaining why for non-trivial changes. Mark breaking changes with `!` and a `BREAKING CHANGE:` footer.
- Author commits as the user alone, with no `Co-Authored-By` or other co-author trailers.
- Commit as the plan progresses. Before pushing, squash related commits into one to keep history clean.
- Push only after the user approves that push.
- Version releases with [Semantic Versioning 2.0.0](https://semver.org/).

## CI

- Keep a CI check only when it catches a concrete failure no existing check covers; identify that failure before adding or retaining it. Apply the test admission rule to CI too.
- Run repository entry points against real inputs or isolated fixtures. Reject duplicate checks, source-text assertions, copied inventories and checks that only prove a command or file exists.
- Name workflows, jobs and steps by their target and action. Propagate command failures; missing prerequisites and skipped required coverage cannot count as success.
- After changing these rules, audit the repository against them. Validate locally, then verify required CI on the pushed commit; report any uncovered contract or unavailable check.

## Docs

- Keep this file, `README.md` and every other doc concise and plain: each sentence carries information, with no filler.
